# Менеджер пакетов Alca (APM)

[English](apm_EN.md) | [Русский](apm_RU.md)

**APM (Alca Package Manager)** — это официальная система управления пакетами и распространения библиотек для языка программирования Alca. APM обеспечивает декларативное управление зависимостями, инициализацию проектов, взаимодействие с распределенными узлами реестра, публикацию предварительно скомпилированных артефактов байткода и криптографическую верификацию целостности.

---

## 1. Архитектура и организация

Экосистема APM состоит из трех согласованных компонентов:
1. **CLI-утилита `apm`** ([`cmd/apm`](../cmd/apm/main.go)): Консольный инструмент для разработчиков и CI/CD пайплайнов.
2. **Ядро `pkg/apm`** ([`pkg/apm`](../pkg/apm)): Библиотека на Go, реализующая парсинг манифестов, SemVer-разрешение графа зависимостей, формирование lockfile и сборку бинарных артефактов.
3. **Сервер реестра `apm-registry`** ([`cmd/apm-registry`](../cmd/apm-registry)): Легковесный сервис реестра для развертывания публичных, корпоративных или локальных репозиториев пакетов.

### Поиск пакетов и импорт без конфигурации
Когда программа на Alca выполняет инструкцию:
```alca
use requests;
```
Модульный резолвер рантайма последовательно проверяет:
1. Локальный относительный путь (`./requests.al` или `./requests/`)
2. Локальные пакеты проекта (`./.alca/packages/requests/`)
3. Глобальный реестр пользователя (`~/.alca/packages/requests/` или `$ALCA_HOME/packages/requests/`)
4. Пространства имен стандартной библиотеки (`std.requests`)

## 2. Справочник команд CLI (`apm`)

Сборка бинарника `apm`:
```bash
go build -o apm ./cmd/apm
```

### `apm init [имя]`
Инициализирует новый проект библиотеки, создавая файл манифеста `alca.toml` и шаблон входной точки `main.al`.

```bash
apm init my-lib
```

### `apm install [<пакет>[@<версия>] ...]`
Устанавливает зависимости, указанные в `alca.toml`, либо загружает пакеты, переданные в аргументах:

```bash
# Установка всех зависимостей проекта из alca.toml
apm install

# Установка конкретной библиотеки
apm install requests

# Установка с явным ограничением версии (SemVer)
apm install requests@^1.4.0
```

Команда автоматически обновляет `alca.lock`, фиксируя версии и контрольные суммы SHA-256.

### `apm install -u <директория>`
Подключает локальный пакет из указанного каталога для отладки и разработки без необходимости публикации в реестр.

### `apm remove <пакет>`
Удаляет библиотеку и очищает ссылки на нее в `alca.toml` и `alca.lock`.

```bash
apm remove requests
```

### `apm show [пакет]`
Выводит список установленных пакетов, их версии и дерево зависимостей.

### `apm search <запрос>`
Выполняет поиск пакетов по имени и описанию в удаленном реестре и среди локально установленных пакетов.

### `apm outdated`
Проверяет наличие более свежих версий зависимостей проекта по сравнению с установленными или зафиксированными в `alca.lock`.

### `apm tree`
Отображает иерархическое дерево зависимостей текущего проекта с версиями и подзависимостями.

### `apm pack [директория]`
Локально валидирует исходный код библиотеки и собирает релизный архив пакета `.tar.gz` без отправки на сервер.

### `apm cache [clean|list|dir]`
Управление локальным дисковым кэшем скачанных архивов пакетов: просмотр пути (`dir`), списка архивов (`list`) и очистка (`clean`).

### `apm run <скрипт>`
Запуск пользовательских сценариев и команд автоматизации, определенных в секции `[scripts]` файла `alca.toml`.

### `apm register [логин] [email]`
Регистрирует новую учетную запись разработчика на активном узле реестра. Генерирует одноразовый криптографический токен доступа.

### `apm login [логин]`
Выполняет авторизацию на сервере реестра и сохраняет учетную запись (логин, пароль и токен) в локальном файле `~/.alca/credentials.json` в зашифрованном виде (AES-256-GCM).

### `apm whoami`
Показывает профиль текущего авторизованного пользователя и адрес активного узла реестра.

### `apm logout`
Отзывает токен на стороне сервера и удаляет сохраненные учетные данные.

### `apm publish`
Проверяет, упаковывает и публикует пакет в реестр:
- Проводит строгую синтаксическую проверку и статический тайпчекинг всех исходных файлов `.al`.
- Упаковывает исходный код в очищенный архив `.tar.gz`.
- Компилирует платформенно-независимые артефакты байткода (`.alca/artifacts/<os>-<arch>.bin`).

## 3. Спецификация манифеста (`alca.toml`)

Каждый пакет Alca описывается файлом `alca.toml` в корне проекта:

```toml
[package]
name = "http-router"
version = "1.2.0"
entry = "src/router.al"
description = "Быстрый URL-маршрутизатор для веб-сервисов Alca"
license = "MIT"
alca = ">=2.0.0"

[dependencies]
json-schema = "^2.0.1"
log-toolkit = "~1.4.0"
crypto-extra = ">=0.8.0, <2.0.0"

[dev-dependencies]
test-runner = "^1.0.0"

[scripts]
test = "alca test tests/"
build = "alca build src/router.al -o bin/router.exe"
start = "alca run src/router.al"
```

### Синтаксис правил SemVer
- `^1.2.3`: Совместимые обновления в рамках мажорной версии (`>=1.2.3, <2.0.0`)
- `~1.2.3`: Патч-обновления (`>=1.2.3, <1.3.0`)
- `>=1.0.0, <3.0.0`: Пользовательский диапазон версий
- `*`: Любая доступная версия

## 4. Файл блокировки (`alca.lock`)

Файл `alca.lock` гарантирует абсолютную воспроизводимость сборок на любых машинах и в CI-пайплайнах:

```json
{
  "version": 1,
  "packages": {
    "json-schema": {
      "version": "2.0.3",
      "sha256": "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855",
      "dependencies": {}
    }
  }
}
```

## 5. Модель безопасности и защита от уязвимостей

В APM на уровне ядра реализован строгий контроль безопасности распаковки архивов:

1. **Защита от Zip-Slip (`pkg/apm/package.go`)**: Все пути внутри tarball-архива проверяются перед извлечением. Любые пути с относительными переходами (`..`), абсолютными корнями (`/`) или префиксами дисков Windows (`C:`) немедленно отклоняются.
2. **Защита от «бомб распаковки» (Decompression Bombs)**:
   - Максимальный размер отдельного файла: **32 МиБ** (`MaxFileBytes`).
   - Максимальный совокупный распакованный объем пакета: **128 МиБ** (`MaxPackageBytes`).
   - Максимальное число файлов в архиве: **2000** (`MaxPackageFiles`).
3. **Блокировка символических ссылок**: Разрешены только обычные файлы (`TypeReg`) и каталоги (`TypeDir`). Символические и жесткие ссылки жестко запрещены для предотвращения побега за пределы песочницы.
4. **Контрольные суммы SHA-256**: Каждый пакет и скомпилированный бинарный артефакт валидируются по хэшу SHA-256 перед установкой в систему.
5. **Шифрование локальных учетных данных (`credentials.json` + `.credentials.key`)**: Учетные данные разработчика (логин, пароль, криптографический токен) сохраняются в локальном файле `~/.alca/credentials.json` в зашифрованном виде с использованием аутентифицированного шифрования **AES-256-GCM**. Локальный ключ генерируется из источника криптографической энтропии (`crypto/rand`) и сохраняется в файле `~/.alca/.credentials.key` с маской прав `0600` (только для владельца) с аппаратной привязкой SHA-256 к локальной системе. Открытые пароли и токены на диске не сохраняются.
