# Архитектура Alca

[English](architecture_EN.md) | [Русский](architecture_RU.md)

Alca использует многоуровневую архитектуру исполнения на основе единого фронтенда:

1. **Bytecode VM (`pkg/vm`)**: Основная высокопроизводительная виртуальная машина со стековыми фреймами, лексическими замыканиями (upvalues), встроенным кэшированием и суперинструкциями.
2. **Интерпретатор (`pkg/interpreter`)**: Эталонный древовидный семантический интерпретатор AST.
3. **JIT-компилятор (`pkg/jit`)**: Многоуровневая JIT-компиляция горячих шаблонов функций прямо в нативный машинный код AMD64.
4. **Нативный компилятор (`cmd/alca/native_build.go`)**: Встроенный генератор исполняемых файлов Windows PE/EXE и DLL на чистом Go.

## Конвейер компиляции и исполнения

```text
исходный код .al
  -> pkg/lexer        токены (скобки, комментарии, литералы, операторы)
  -> pkg/parser       парсер Пратта, AST (pkg/ast), структурированная диагностика
  -> pkg/typecheck    строгая статическая типизация, области видимости, таблицы сигнатур stdlib
  -> Уровни исполнения:
       ├── pkg/vm           байткод-компилятор + VM (по умолчанию)
       ├── pkg/interpreter  древовидный интерпретатор (эталонная семантика)
       ├── pkg/jit          многоуровневый JIT-компилятор
       └── Native AOT       автономный бинарник PE/EXE или нативная библиотека DLL
```

Все движки разделяют общую среду рантайма:
- `pkg/stdlib` регистрирует модули и встроенные функции более чем в 20 доменах.
- `pkg/interpreter` содержит модели значений рантайма, окружение и базовые builtins.
- `pkg/vm` взаимодействует с общей средой builtins, гарантируя паритет семантики.

## Парсер и синтаксис

`pkg/parser` — это парсер Пратта, регистрирующий ошибки с указанием строк и колонок в исходном коде:
- **Блоки кода**: Канонический синтаксис использует фигурные скобки `{ ... }`. Двоеточие `:` с отступами поддерживается для совместимости.
- **Объявления**: `fn name(params) -> ReturnType { ... }` или `pub fn`. Переменные объявляются через `name: Type = val;` или `name := val;`.
- Строгий тайпчек гарантирует однозначную семантику каждого узла AST во всех движках.

## Проверка типов (Type Checker)

`pkg/typecheck` — выделенный проход статического анализа без побочных эффектов во время выполнения. Он обеспечивает:
- Фиксированные выведенные типы без неявных числовых или строковых приведений.
- Сужение типов nullable (`T | null`) после проверок `!= null`.
- Проверку сигнатур функций и методов стандартной библиотеки.
- Запрет затенения переменных (shadowing) в одной области видимости.
- Строгую типизацию условий: выражения в `if`/`while` обязаны иметь тип `bool`.
- Изоляцию динамических типов: `json` — единственный динамический тип.

## Конкурентность и Async/Await

Alca предоставляет два уровня конкурентности:
1. **Промышленная конкурентность (`@ba` и `@threads`)**:
   - `@ba { ... }` исполняет изолированные фоновые асинхронные задачи с тайм-аутами.
   - `@threads(N) { ... }` исполняет задачи в управляемом пуле воркеров.
2. **Синтаксис `async` / `await`**:
   - Ключевые слова `async` и `await` парсятся, проверяются тайпчекером и выполняются кооперативно обоими движками (VM и интерпретатором).
   - Полноценный асинхронный цикл событий Promise/Future запланирован в версии v2.1.

## Уровни исполнения

### 1. Bytecode VM
`pkg/vm` компилирует AST в байткод-инструкции:
- Замыкания используют upvalues (`OpClosure`, `OpGetFree`, `OpSetFree`) для захвата переменных по ссылке.
- Конструкции, не поддерживаемые байткод-компилятором, возвращают явную ошибку `*vm.UnsupportedError`.
- `alca run` автоматически переключается на эталонный интерпретатор при наличии динамических макросов; `alca run --vm` строго сообщает об ошибке.

### 2. Движок JIT
Компилятор JIT (`pkg/jit`) компилирует шаблоны функций в машинный код AMD64. Скомпилированные артефакты разделяются между экземплярами одной функции, строго ограничиваясь `jit.Config.MaxArtifacts`.

### 3. Автономные бинарники (Native AOT)
`cmd/alca/native_build.go` и `pkg/compiler` создают автономные файлы:
- Генерация бинарников Windows Portable Executable (PE) 32/64-бит и DLL напрямую из Go без внешних компиляторов C.
- Сжатие встроенных данных gzip с проверкой контрольных сумм SHA-256.

## Песочница и безопасность

`pkg/sandbox` реализует модель безопасности с гранулярными правами (deny-by-default):
- `--allow-read[=<путь>]`: Чтение файлов.
- `--allow-write[=<путь>]`: Запись файлов.
- `--allow-net[=<хост[:порт]>]`: Сетевые сокеты и HTTP.
- `--allow-run[=<команда>]`: Запуск подпроцессов (`exec.Command`).
- `--allow-env[=<переменная>]`: Чтение и запись переменных окружения.
- `--allow-ffi[=<библиотека>]`: Загрузка динамических библиотек (.dll, .so).
- `--allow-all`: Безусловное предоставление всех прав.
