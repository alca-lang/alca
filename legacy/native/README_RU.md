# Pawl Native Toolchain (C++ bootstrap)

Цель: собирать проекты Pawl **без Go, без VM, без байткода, без системного ассемблера,
линкера и транспиляции**. Компилятор сам генерирует машинные инструкции x86-64 и сам
формирует PE32+ (Windows) или ELF64 (Linux).

Это первый рабочий срез (Stage 0). Он уже доказывает ключевое: **в момент сборки
Pawl-проекта не вызывается ни один системный инструмент, и в выходном файле нет
никакого рантайма Go.**

## Что уже работает

Поддерживаемое подмножество языка:

- `int`, `string`, `bool` (представлен как `int`), `void`;
- переменные (`x := ...`, `x: int = ...`), присваивание;
- `if` / `else`, `while`;
- функции до 4 параметров, рекурсия, `return`;
- `print` / `println` (int и string), `exit`;
- арифметика `+ - * / %`, сравнения `== != < <= > >=`, унарный минус.

Проверено на Windows x86-64:

```
hello from native Pawl
55
55
-42
```

Размер собранного `hello.exe` — **2560 байт**. Импорты PE — только
`KERNEL32.dll: ExitProcess, GetStdHandle, WriteFile`. Ни `Go build`, ни `runtime.`,
ни байткода, ни libc.

ELF64 для Linux собирается тем же компилятором: валидный `ET_EXEC`, два `PT_LOAD`,
вход `0x401000`, вывод — через raw syscall'ы `write` и `exit`, без libc.

## Чего ещё нет (честно)

- импорты/модули (`use`) — парсятся, но пока игнорируются;
- `for`, диапазоны, `list`, `map`, `struct`, `class`, `enum`, `interface`, замыкания;
- строковые операции (`+`, сравнение, срезы), кроме печати литералов;
- вся стандартная библиотека;
- песочница (capabilities);
- ARM64 и ARM64 PE/ELF;
- сборка `.dll` / `.so`.

## Сборка компилятора

Компилятор написан на C++17. `g++` нужен **только чтобы один раз собрать сам `pawlc`**;
при компиляции Pawl-проектов он не вызывается.

```powershell
# Windows (MSYS2 UCRT64 g++)
g++ -std=c++17 -O2 -static -o build/pawlc.exe `
    src/front.cpp src/codegen.cpp src/link.cpp src/main.cpp

# либо
powershell -ExecutionPolicy Bypass -File build.ps1
```

```bash
# Linux / macOS (для сборки самого компилятора)
make
```

## Использование

```powershell
build\pawlc.exe examples\hello.al -o out\hello.exe --target windows
build\pawlc.exe examples\hello.al -o out\hello.elf --target linux
```

Запуск smoke-теста:

```powershell
powershell -ExecutionPolicy Bypass -File tests\smoke.ps1
```

## Архитектура

```
native/
  src/front.h, front.cpp     лексер + рекурсивный парсер + AST
  src/codegen.h, codegen.cpp x86-64 кодогенерация + runtime-заглушки (raw bytes)
  src/link.h, link.cpp       собственные PE32+ и ELF64 писатели
  src/main.cpp               CLI
  examples/hello.al
  tests/smoke.ps1
```

Ключевые свойства:

1. **Нет внешнего ассемблера.** Байты инструкций формируются в `codegen.cpp`.
2. **Нет внешнего линкера.** PE/ELF-заголовки, таблицы импорта, секции и
   релокации считаются в `link.cpp`.
3. **Нет libc в выходном файле.** Windows — только `kernel32`; Linux — syscall'ы.
4. **Нет Go.** Ни в компиляторе, ни в рантайме, ни в артефактах.

## Дорожная карта до полного паритета

Stage 0 (сделано): срез языка + PE/ELF x86-64, доказательство архитектуры.

Stage 1 — язык и модули:
- резолвер `use` (локальные файлы и APM), пространства имён, сборка всех модулей в один IR;
- полный core: `for`, диапазоны, `list`, `map`, `struct`, `class`, `enum`, `error`;
- строки: конкатенация, сравнение, срезы, Unicode;
- аллокатор и сборка мусора (или arena/refcount) в нативном рантайме;
- ABI значений (тегированное представление), вызовы методов, исключения/ошибки.

Stage 2 — системный рантайм:
- файлы, каталоги, процессы, окружение, время, stdin/stdout/stderr;
- capability-песочница (deny-by-default) внутри рантайма, а не в компиляторе;
- статическая линковка рантайма: его машинный код компилируется один раз при сборке
  `pawlc` и встраивается в компилятор, чтобы при сборке Pawl-проекта не вызывать
  системный компилятор.

Stage 3 — ARM64:
- отдельный кодогенератор AArch64;
- PE32+ ARM64 и ELF64 AArch64;
- единый IR, два бэкенда.

Stage 4 — stdlib (полный паритет):
- math/strings/collections/json/csv/regex/time/fs/os/process/env;
- crypto (AES, SHA, HMAC, RSA), сжатие (zlib/gzip), архивы (zip/tar);
- сеть: TCP/UDP, HTTP-клиент и сервер, WebSocket, TLS;
- БД: sqlite и сетевые драйверы;
- GUI: Win32, X11/Wayland, Cocoa; webview;
- прочее: реестр/службы/WMI, sensors, libtorch.

Это самая большая часть: в текущем Go-рантайме stdlib — ~24k строк и ~40 модулей,
часть которых опирается на Go-стандартную библиотеку (HTTP, TLS, SQL-драйверы).
Полный паритет — это отдельный многолетний трек; инфраструктура выше позволяет
делать его модуль за модулем без Go.

## Ограничения текущего среза

- только x86-64;
- не более 4 параметров у функции;
- нет проверки выхода за границы, нет GC — строки и числа живут в статическом пуле;
- `println` принимает один аргумент;
- ошибки компиляции без файла/строки в части парсера.

Эти ограничения снимаются в Stage 1–2.
