## 1. Введение и архитектура платформы

**Alca** — это статически типизированный язык программирования общего назначения, спроектированный для создания автономных, надежных и производительных системных утилит и кроссплатформенных приложений.

### Ключевые преимущества:
- **Zero-Toolchain Distribution:** Компиляция в полностью самодостаточные исполняемые файлы Windows PE/EXE (`alca build`) и нативные DLL библиотеки (`alca dll`) без необходимости устанавливать компиляторы C/C++ (MSVC, MinGW или Clang).
- **Четырехуровневое исполнение:**
  1. *Bytecode Virtual Machine (VM)* — быстрый стековый/регистровый виртуальный процессор.
  2. *Multi-Tier AMD64 JIT* — нативная JIT-компиляция горячих функций и циклов прямо в машинный код.
  3. *Reference Interpreter* — эталонный древовидный интерпретатор с полной поддержкой динамических инспекций и метапрограммирования.
  4. *Native PE / DLL AOT Generator* — встроенный генератор бинарных файлов PE/COFF.
- **Песочница на основе возможностей (Capability-Based Sandbox):** Полный контроль доступа к файловой системе, сети, процессам, переменным окружения и нативным библиотекам по принципу *Deny-by-Default*.

## 2. Синтаксис, лексика и структура программы

Программа на языке Alca представляет собой последовательность инструкций. Файлы исходного кода имеют расширение `.al`.

### 2.1 Разделители и блоки
- Каждая простая инструкция завершается точкой с запятой (`;`).
- Блоки кода оформляются **каноническими фигурными скобками `{ ... }`** либо двоеточием с табуляцией/отступами в 4 пробела:

```alca
// Вариант 1: Канонические фигурные скобки (рекомендуется)
fn max(a: int, b: int) -> int {
    if a > b {
        return a;
    }
    return b;
}

// Вариант 2: Двоеточие и отступы
fn min(a: int, b: int) -> int:
    if a < b:
        return a;
    return b;
```

### 2.2 Комментарии
```alca
// Однострочный комментарий

/*
  Многострочный
  блок комментариев
*/
```

### 2.3 Импорт модулей
Ключевое слово `use` подключает модули стандартной библиотеки или локальные файлы:
```alca
use std.math;
use std.io;
use "./helpers.al";
```

## 3. Система типов и безопасность

Alca применяет **строгую статическую типизацию** с двунаправленным выводом типов. В языке отсутствуют неявные приведения (coercions) между числовыми типами и строками.

### 3.1 Примитивные типы
- `int` — 64-битное знаковое целое число.
- `float` — 64-битное число с плавающей точкой двойной точности (IEEE 754).
- `string` — неизменяемая последовательность символов UTF-8.
- `bool` — логический тип (`true`, `false`).
- `void` — тип отсутствия возвращаемого значения для функций.

### 3.2 Объявление переменных и вывод типов
```alca
// Явное указание типа
counter: int = 0;
pi: float = 3.14159265;
title: string = "Alca Language";
is_ready: bool = true;

// Вывод типа (Type Inference через оператор `:=`)
// Тип фиксируется на этапе компиляции раз и навсегда!
ratio := 2.5;                // float
names := ["Alice", "Bob"];   // list[string]

// Повторное объявление (Shadowing) в той же или вложенной области видимости запрещено:
// counter: int = 5;         // ОШИБКА КОМПИЛЯЦИИ: variable 'counter' already declared
counter = 5;                 // Корректно: присваивание нового значения
```

### 3.3 Арифметика и строгая типизация
Смешивание типов в арифметических выражениях вызывает ошибку компилятора:
```alca
x: int = 10;
y: float = 2.5;

// total := x + y;            // ОШИБКА: operator '+' cannot be applied to int and float
total := float(x) + y;        // Корректно: 12.5

// Деление:
int_res := 7 / 2;             // Целочисленное деление: 3
float_res := float(7) / 2.0;  // Вещественное деление: 3.5
```

### 3.4 Защита от Null (Null-Safety)
Значение `null` не может быть присвоено обычной переменной. Если значение может отсутствовать, тип объявляется как `T | null`:
```alca
user_name: string | null = null;

// Прямой доступ к полям или методам nullable-значений блокируется тайпчекером:
// len(user_name);            // ОШИБКА: value may be null

// Безопасное сужение типа (Type Narrowing) через проверку:
if user_name != null {
    // Внутри этого блока тип user_name автоматически сужается до `string`
    println("Длина имени: " + string(len(user_name)));
}
```

### 3.5 Динамический шлюз `json`
Тип `json` — это единственный динамический тип в языке, используемый для работы с произвольными структурами данных (API, внешние конфиги). Перед использованием в строго типизированном коде его значения требуют явного приведения.

## 4. Управляющие конструкции и операторы

### 4.1 Операторы сравнения и эквивалентности
- `==` и `!=` — структурное сравнение значений по содержимому. Сравнение несовместимых типов (например, `1 == "1"`) отвергается компилятором.
- `===` и `!==` — строгая проверка идентичности ссылок/указателей в памяти.
- `<`, `<=`, `>`, `>=` — операторы порядка.

### 4.2 Логические операторы
- Логическое И: `and` (или `&&`).
- Логическое ИЛИ: `or` (или `||`).
- Логическое НЕ: `not` (или `!`).

> Условия в `if`, `elif`, `while` обязаны строго возвращать тип `bool`. Понятия «truthy/falsy» в Alca отсутствуют (число 0 или пустая строка не равны `false`).

### 4.3 Диапазоны (Ranges)
- `a..b` — полуоткрытый интервал $[a, b)$. Число $b$ не включается:
  ```alca
  for i in 0..3 {
      // i принимает значения: 0, 1, 2
  }
  ```
- `a..=b` — замкнутый интервал $[a, b]$. Число $b$ включается:
  ```alca
  for i in 0..=3 {
      // i принимает значения: 0, 1, 2, 3
  }
  ```

### 4.4 Циклы и прерывания
Поддерживаются операторы `break` и `continue`:
```alca
// Обход коллекций
users := ["Alex", "Maria", "Ivan"];
for u in users {
    if u == "Maria" {
        continue;
    }
    println("Пользователь: " + u);
}

// Цикл While
n := 5;
while n > 0 {
    n = n - 1;
}
```

### 4.5 Функциональные конвейеры (Pipeline Operator `|>`)
Оператор конвейера `|>` передает результат выражения слева в качестве первого аргумента в функцию справа. Это устраняет глубокую вложенность скобок и выстраивает код в естественную цепочку преобразования данных слева направо:

```alca
fn double(x: int) -> int { return x * 2; }
fn add(x: int, y: int) -> int { return x + y; }
fn to_str(x: int) -> string { return "Результат: " + string(x); }

// Цепочка вызовов функций одного аргумента:
val := 10 |> double; // 20

// Вызов функции с дополнительными аргументами (первый аргумент подставляется автоматически):
res := 5 |> double |> add(3) |> to_str; 
// Эквивалентно: to_str(add(double(5), 3)) -> "Результат: 13"
```

### 4.6 Потоковые конвейеры ввода-вывода (Stream Pipelines)
В Alca встроена развитая система потоковых конвейеров ввода-вывода, позволяющая перенаправлять данные между переменными, файлами, сетевыми эндпоинтами и потоками ввода/вывода с контролем прав песочницы:

| Оператор | Название | Назначение и поведение |
| --- | --- | --- |
| `>>` | STREAM_APPEND | Дозапись строки/значения в файл или сетевой URL (POST) с переносом строки. |
| `>!` | STREAM_OVERWRITE | Полная перезапись содержимого целевого файла (или сетевой POST). |
| `>>>` | STREAM_VAR | Потоковое сохранение значения выражения в переменную. |
| `<<` | STREAM_IN | Потоковое чтение из файла или системного потока ввода (`stdin` / `console`). |
| `&>>` | STREAM_ASYNC | Асинхронная потоковая дозапись в фоновой горутине без блокировки. |
| `&&>>` | STREAM_THREAD | Асинхронный сетевой стрим в фоновом потоке. |
| `?>>` | STREAM_ERR | Перенаправление ошибки (если источник — `error`) в лог-файл. |
| `?>>>` | STREAM_ERR_VAR | Перехват объекта ошибки в переменную без аварийного завершения программы. |

#### Примеры использования потоковых конвейеров:

```alca
// 1. Потоковая запись и дозапись в файл:
"Инициализация системы..." >! "app.log";        // Перезапись (>!)
"[INFO] Сервис авторизации готов" >> "app.log"; // Дозапись (>>)

// 2. Потоковое чтение из файла или консоли:
config_data << "config.json";  // Чтение файла в переменную config_data
user_input << console;         // Чтение строки из stdin

// 3. Сохранение промежуточного результата в переменную:
(math.sqrt(144.0) * 2.0) >>> computed_val;
assert computed_val == 24.0;

// 4. Потоковая отправка по сети (Webhook / API):
"{\"status\": \"heartbeat\"}" >> "https://monitoring.internal/api/beat";

// 5. Асинхронный неблокирующий стриминг (&>>):
// Запись тяжелых логов выполняется в фоновой горутине, не задерживая основной цикл:
heavy_payload &>> "audit_archive.log";

// 6. Сброс потока в null (отбрасывание вывода):
debug_trace >> "/dev/null"; // также поддерживаются "null" и "NUL"
```

## 5. Функции, замыкания и асинхронность

### 5.1 Объявление функций
Функции объявляются ключевыми словами `fn` или `func`:
```alca
pub fn calculate_discount(price: float, rate: float = 0.1) -> float {
    return price * (1.0 - rate);
}

// Функции, не возвращающие значения
void log_event(event: string) {
    println("[LOG] " + event);
}
```

### 5.2 Замыкания и функции высшего порядка
Функции в Alca являются объектами первого класса (first-class citizens):
```alca
fn make_prefixer(prefix: string) -> func {
    fn format(msg: string) -> string {
        return prefix + ": " + msg;
    }
    return format;
}

logger := make_prefixer("[SYSTEM]");
println(logger("Startup OK")); // "[SYSTEM]: Startup OK"
```

### 5.3 Асинхронность (`async` / `await`)
В версии Alca 2.0 реализован полный паритет для `async` и `await` на обоих движках (Bytecode VM и Interpreter):
```alca
async fn load_remote_config(url: string) -> string {
    return "{\"status\": \"ok\"}";
}

cfg := await load_remote_config("https://config.server.local");
```

### 5.4 Конкурентность: фоновые задачи (`@ba`) и пулы потоков (`@threads`)
- `@ba` (Background Actions) запускает изолированную задачу в фоне:
  ```alca
  ba(timeout=10s):
      println("Фоновая синхронизация завершена");
  ```
- `@threads` распределяет вычисления по пулу системных потоков:
  ```alca
  threads 8:
      println("Параллельная обработка пакета данных");
  ```

## 6. Объектно-ориентированное и контрактное программирование

### 6.1 Структуры (`struct`)
Легковесные структуры данных:
```alca
struct Point {
    x: int;
    y: int = 0;
}

pt := Point(10, 20);
pt.x = 25;
```

### 6.2 Классы и одиночное наследование (`class`)
Классы поддерживают инкапсуляцию полей (`pub`, `private`), методы, обращение к текущему объекту через `self` и вызов методов родителя через `super`:
```alca
class Vehicle {
    pub brand: string;
    private mileage: int = 0;

    pub fn drive(km: int) -> void {
        self.mileage = self.mileage + km;
    }

    pub fn get_mileage() -> int {
        return self.mileage;
    }
}

class ElectricCar extends Vehicle {
    pub battery_level: int = 100;

    pub fn drive(km: int) -> void {
        super.drive(km);
        self.battery_level = self.battery_level - (km / 10);
    }
}

tesla := ElectricCar("Tesla", 0, 100);
tesla.drive(50);
assert tesla.get_mileage() == 50;
assert tesla.battery_level == 95;
```

### 6.3 Перечисления и сопоставление с образцом (`enum`, `match`)
```alca
enum ConnectionState {
    Disconnected,
    Connecting,
    Connected = 10,
}

state := ConnectionState.Connected;
match state {
    case ConnectionState.Disconnected:
        println("Нет связи");
    case ConnectionState.Connecting:
        println("Установка соединения...");
    case ConnectionState.Connected:
        println("Соединение активно!");
    else:
        println("Неизвестный статус");
}
```

### 6.4 Интерфейсы (`interface`)
Интерфейсы задают проверяемые на этапе компиляции контракты:
```alca
interface StorageDriver {
    fn write_chunk(data: string) -> bool;
    fn read_chunk() -> string;
}

class LocalDiskStorage {
    pub fn write_chunk(data: string) -> bool {
        return true;
    }
    pub fn read_chunk() -> string {
        return "data";
    }
}

driver: StorageDriver = LocalDiskStorage();
driver.write_chunk("payload");
```

## 7. Обработка ошибок и отказоустойчивость

Вместо скрытого раскручивания стека исключений (exceptions) Alca использует **явные значения ошибок** и операторы потоков ошибок.

### 7.1 Оператор перехвата `?>>>`
Оператор `expr ?>>> target` направляет возникшую ошибку в переменную типа `error | null`:
```alca
use std.io;

failure: error | null = null;
data := io.read_file("nonexistent.txt") ?>>> failure;

if failure != null {
    println("Код ошибки: " + string(failure.code));
    println("Описание: " + failure.msg);
} else {
    println("Файл прочитан: " + data);
}
```

### 7.2 Перенаправление ошибок в лог `?>>`
Оператор `expr ?>> "path/to/log.txt"` перенаправляет текст возникшей ошибки напрямую в файл на диске.

### 7.3 Коды ошибок и проверки
- `400` — неверные аргументы или формат данных (Bad Request).
- `403` — отказ в доступе песочницы (Permission Denied).
- `500` — внутренняя ошибка выполнения (Internal Runtime Error).
- `507` — превышение выделенной памяти (OOM Guard).
- Встроенные функции: `is_permission_error(err)` для быстрой проверки прав песочницы.

## 8. Глобальные встроенные функции и системные переменные

Глобальные встроенные функции доступны во всей программе **без необходимости импорта каких-либо модулей** (`use` не требуется). Они компилируются напрямую в высокопроизводительные опкоды виртуальной машины или разрешаются через встроенную таблицу окружения.

### 8.1 Терминальный ввод-вывод
```alca
// print(...args) -> string — вывод аргументов через пробел без перевода строки
print("Старт вычислений:", 100);

// println(...args) -> string — вывод аргументов через пробел с автоматическим переводом строки
println("Готово!", 200, true);

// input(prompt?: string) -> string — чтение строки из стандартного ввода (stdin) с опциональным приглашением
name := input("Введите ваше имя: ");
println("Привет, " + name);
```

### 8.2 Инспекция типов и размера
```alca
// len(collection) -> int — длина строки (число символов/рун), списка, словаря или байт-буфера
assert len("Привет") == 6;
assert len([1, 2, 3, 4]) == 4;
assert len({"a": 1, "b": 2}) == 2;

// type(val) / typeof(val) -> string — строковое имя типа значения
assert type(42) == "int";
assert type(3.14) == "float";
assert type("hello") == "string";
assert type(true) == "bool";
assert type([1, 2]) == "list";
assert type({"k": "v"}) == "map";
assert type(null) == "null";
```

### 8.3 Явные конструкторы типов (Type Casting)
Поскольку в Alca отсутствует неявное приведение типов, конструкторы используются для строгой и безопасной конвертации:
```alca
// int(x) -> int
assert int(4.99) == 4;          // Усечение к нулю
assert int("123") == 123;       // Парсинг строки в целое число
assert int(true) == 1;

// float(x) -> float
assert float(10) == 10.0;
assert float("2.718") == 2.718;

// string(x) -> string
assert string(100) == "100";
assert string(3.14) == "3.14";
assert string(null) == "null";

// bool(x) -> bool
assert bool(1) == true;
assert bool(0) == false;

// list(x) -> list
chars := list("ABC");           // ["A", "B", "C"]
keys_list := list({"x": 1});    // ["x"]
```

### 8.4 Манипуляция коллекциями без импортов
```alca
items := [10, 20];

// append(list, elem) -> list — возвращает новый список с добавленным элементом
new_items := append(items, 30); // [10, 20, 30]

// push(list, elem) -> list — мутирует существующий список на месте
push(items, 30);
assert len(items) == 3;

// pop(list) -> any — извлекает и удаляет последний элемент списка
last_val := pop(items);
assert last_val == 30;

// keys(map) / values(map) — извлечение списков ключей и значений словаря
user := {"name": "Alex", "role": "admin"};
assert len(keys(user)) == 2;
assert len(values(user)) == 2;

// range(start, end, step? = 1) -> list[int] — генерация списка целых чисел
seq := range(1, 5); // [1, 2, 3, 4, 5]
```

### 8.7 Встроенный JSON и модуль `std.json`
В Alca доступны как глобальные вспомогательные функции JSON без импорта, так и полноценный модуль `std.json`:

```alca
// Глобальные функции без импорта:
// json_encode(val) -> string — сериализация в компактный JSON
data := {"status": 200, "ok": true};
raw_json := json_encode(data);

// json_decode(str) -> json — парсинг строки в динамический объект json
parsed := json_decode(raw_json);
assert parsed["status"] == 200;

// json_prettify(val) -> string — форматирование с отступами для печати
pretty := json_prettify(data);

// json_query(json, query) -> json — извлечение по точечному пути
val := json_query(parsed, "status");
assert val == 200;

// Модуль std.json (use std.json;):
use std.json;
doc := json.parse("{\"score\": 98}");
assert json.validate("{\"score\": 98}") == true;
compact := json.encode(doc);
formatted := json.prettify(doc, "  ");
```

### 8.9 Системные переменные рантайма (Dunder Variables)
Во время исполнения компилятор автоматически предоставляет контекстные переменные с двойным подчеркиванием:

| Переменная | Тип | Описание |
| --- | --- | --- |
| `__file__` | `string` | Абсолютный путь к файлу текущего исходного кода. |
| `__dir__` / `__dirname__` | `string` | Абсолютный путь к каталогу, в котором расположен исполняемый файл. |
| `__line__` | `int` | Текущий номер строки в исходном коде. |
| `__name__` | `string` | Имя модуля или `"__main__"` для главного скрипта. |
| `__version__` | `string` | Текущая версия рантайма Alca (например, `"1.7.9"`). |

```alca
println("Исполняется файл: " + __file__);
println("Каталог: " + __dir__);
println("Строка кода: " + string(__line__));
println("Версия Alca: " + __version__);
```

### 8.10 Разделение пространств имен стандартной библиотеки (устаревание глобальных алиасов)
Для обеспечения чистоты глобального пространства имен, надежного статического анализа и строгого аудита безопасности прежние глобальные псевдонимы функций стандартной библиотеки удалены из глобальной области. Попытка их вызова напрямую вызывает ошибку компиляции с указанием соответствующего модуля:

- **Файловая система (`use std.io;`):** `io.read_file`, `io.write_file`, `io.append_file`, `io.file_exists`, `io.file_size`, `io.delete_file`, `io.list_dir`, `io.make_dir`.
- **Криптография (`use std.crypto;`):** `crypto.uuid`, `crypto.random_string`, `crypto.random_int`, `crypto.hex_encode`, `crypto.hex_decode`, `crypto.sha256`, `crypto.sha512`.
- **Процессы и метрики (`use std.process;`):** `process.cpu_count`, `process.memory_usage`, `process.uptime`, `process.exec_cmd`, `process.exec_bg`.
- **Окружение (`use std.env;`):** `env.home_dir`, `env.hostname`, `env.username`, `env.is_windows`, `env.is_linux`, `env.get_env`, `env.set_env`.

## 9. Песочница и безопасность (Capability-Based Sandbox)

Alca реализует модель безопасности с гранулярными правами доступа. По умолчанию скрипт **не имеет прав** на чтение/запись файлов, сеть, подпроцессы, переменные окружения и FFI.

### Флаги запуска:
| Флаг | Назначение | Пример использования |
| --- | --- | --- |
| `--allow-read` | Чтение любых файлов | `alca run --allow-read app.al` |
| `--allow-read=<path>` | Чтение только конкретного каталога | `alca run --allow-read=./data app.al` |
| `--allow-write` | Запись в любые файлы | `alca run --allow-write app.al` |
| `--allow-write=<path>` | Запись только в целевую директорию | `alca run --allow-write=./logs app.al` |
| `--allow-net` | Неограниченный сетевой доступ | `alca run --allow-net app.al` |
| `--allow-net=<host>` | Доступ только к хосту/домену | `alca run --allow-net=api.site.com:443 app.al` |
| `--allow-run` | Разрешение запуска процессов (`exec`) | `alca run --allow-run app.al` |
| `--allow-run=<cmd>` | Запуск конкретного бинарника | `alca run --allow-run=git app.al` |
| `--allow-env` | Чтение системных переменных окружения | `alca run --allow-env app.al` |
| `--allow-env=<var>` | Доступ к конкретной переменной | `alca run --allow-env=PORT app.al` |
| `--allow-ffi` | Загрузка внешних динамических библиотек | `alca run --allow-ffi app.al` |
| `--allow-all` | Полный доступ (все capabilities) | `alca run --allow-all app.al` |

## 10. Полный справочник стандартной библиотеки (Stdlib)

Модули импортируются через `use std.<имя_модуля>;`.

<a id="101-коллекции-и-структуры-данных"></a>
### 10.1 Коллекции и структуры данных (`list`, `map`, `string`)
- **Списки (`std.list`)**:
  - `list.len(l)` — длина списка.
  - `list.append(l, item)` — добавление элемента.
  - `list.sort(l)` — сортировка по возрастанию.
  - `list.reverse(l)` — обратный порядок элементов.
  - `list.any(l, predicate)`, `list.all(l, predicate)` — проверка условий.
- **Словари (`std.map`)**:
  - `map.has_key(m, key)` — проверка наличия ключа.
  - `map.delete_key(m, key)` — удаление пары по ключу.
  - `map.keys(m)` — список всех ключей.
  - `map.values(m)` — список всех значений.
- **Строки (`std.string`)**:
  - `str.contains(s, sub)`, `str.starts_with(s, prefix)`, `str.ends_with(s, suffix)`.
  - `str.lower(s)`, `str.upper(s)`, `str.trim(s)`.
  - `str.split(s, sep)`, `str.join(list, sep)`.
  - `str.replace(s, old, new)`.

<a id="102-ввод-вывод-и-файловая-система"></a>
### 10.2 Ввод-вывод и файловая система (`io`, `path`, `archive`, `compress`)
- **`std.io`**:
  - `io.read_file(path)` — чтение содержимого текстового файла в `string`.
  - `io.write_file(path, content)` — перезапись файла.
  - `io.append_file(path, content)` — дозапись в конец файла.
  - `io.file_exists(path)` — проверка существования файла или папки.
  - `io.file_size(path)` — размер файла в байтах.
  - `io.delete_file(path)` — удаление файла.
  - `io.make_dir(path)`, `io.list_dir(path)`.
- **`std.path`**:
  - `path.join(p1, p2, ...)` — кроссплатформенная склейка путей.
  - `path.base(p)` — имя файла, `path.dir(p)` — родительский каталог, `path.ext(p)` — расширение.
- **`std.archive` / `std.compress`**:
  - `archive.zip(src_dir, out_zip)` — архивация.
  - `archive.unzip(zip_path, target_dir)` — безопасная распаковка с защитой от Zip-Slip.
  - `compress.gzip(data)`, `compress.gunzip(data)`.

<a id="103-сеть-и-web"></a>
### 10.3 Сеть и Web (`net`, `http`, `urllib2`)
- **`std.http` (HTTP-сервер и роутинг)**:
  - Создание сервера, регистрация обработчиков `router.get("/", handler)`, запуск на порту:
    ```alca
    use std.http;

    router := http.new_router();
    router.get("/api/status", fn(req: http.Request) -> http.Response {
        return http.json_response(200, "{\"status\": \"healthy\"}");
    });
    ```
- **`std.urllib2` (HTTP-клиент)**:
  - `urllib2.get(url, headers)` — выполнение GET-запроса.
  - `urllib2.post(url, body, headers)` — выполнение POST-запроса.
  - Поддержка постоянных соединений WebSocket.
- **`std.mtproto` (Telegram-клиент)**:
  - Реализация протокола MTProto v2.0 (клиент Telegram, Diffie-Hellman, шифрование AES-IGE, сериализация TL). См. [stdlib_RU.md](stdlib_RU.md#mtproto).

<a id="104-криптография-и-безопасность"></a>
### 10.4 Криптография и безопасность (`crypto`)
- `crypto.sha256(data)` — дайджест SHA-256 (64 hex-символа).
- `crypto.sha512(data)` — дайджест SHA-512.
- `crypto.hmac_sha256(key, data)` — вычисление HMAC подписи.
- `crypto.constant_time_equal(a, b)` — сравнение строк за постоянное время (защита от timing attacks).
- `crypto.base64_encode(data)`, `crypto.base64_decode(str)`.
- `crypto.hex_encode(data)`, `crypto.hex_decode(str)`.
- `crypto.uuid()` — криптостойкий UUID v4.
- `crypto.random_string(len, charset)`, `crypto.random_int(min, max)`.

<a id="105-форматы-данных-и-конфигурация"></a>
### 10.5 Форматы данных и конфигурация (`json`, `csv`, `ini`, `marshal`)
- **`std.json`**:
  - `json.read(str)` — парсинг строки в динамический объект `json`.
  - `json.format(obj)` — сериализация объекта в JSON-строку.
- **`std.csv`**:
  - `csv.read(str_or_path)` — чтение двумерной таблицы CSV в список строк.
  - `csv.write(table)` — генерация CSV-текста.
- **`std.ini`**:
  - `ini.read(str_or_path)` — парсинг секций и параметров INI-конфигурации.

<a id="106-время-даты-и-бенчмарки"></a>
### 10.6 Время, даты и бенчмарки (`time`)
- `time.now()` — текущий таймштамп Unix в секундах.
- `time.now_ms()` — точный таймштамп в миллисекундах (для замеров производительности).
- `time.format(ts, layout, tz)` — форматирование даты по шаблону (`YYYY-MM-DD HH:mm:ss`).
- `time.parse(str, layout, tz)` — парсинг строки даты.
- `time.date(ts, tz)` — получение словаря компонентов (`year`, `month`, `day`, `hour`, `minute`, `second`).
- `time.diff(t1, t2)` — разница между временами в секундах.
- `time.sleep(ms)` — приостановка выполнения на указанное число миллисекунд.

<a id="107-математика-и-вычисления"></a>
### 10.7 Математика, глубокое обучение и вычисления (`math`, `libtorch`)
- `std.math`:
  - `math.PI`, `math.E` — математические константы.
  - `math.sin`, `math.cos`, `math.tan`, `math.sqrt`, `math.pow(x, y)`.
  - `math.round(x)`, `math.floor(x)`, `math.ceil(x)`, `math.abs(x)`.
  - Матричные и векторные операции: `math_vector`, `math_matrix`, `math_quat`.
- `std.libtorch`:
  - 85 функций машинного обучения, многомерные тензоры с поддержкой цепочки ООП-методов (`x.matmul(w).relu()`), автоматическое дифференцирование (Autograd), оптимизаторы и аппаратное ускорение CUDA. См. [stdlib_RU.md](stdlib_RU.md#libtorch).

<a id="108-системные-процессы-и-окружение"></a>
### 10.8 Системные процессы и окружение (`sys`, `process`, `env`, `cli`)
- `sys.os()`, `sys.arch()` — определение операционной системы и архитектуры ЦП.
- `env.get("NAME")`, `env.set("NAME", "VAL")` — работа с переменными окружения (требует `--allow-env`).
- `process.run("cmd", args)` — запуск внешнего подпроцесса (требует `--allow-run`).
- `cli.args()` — доступ к аргументам командной строки.

<a id="109-нативная-интеграция-и-ос"></a>
### 10.9 Нативная интеграция (FFI) и ОС (`ffi`, `win32`, `devices`, `power`)
- `ffi.open(lib_path)` — открытие динамической библиотеки (`.dll` / `.so`).
- `ffi.call(sym, args...)` — прямой вызов C-функций по соглашению cdecl/stdcall.
- `std.win32` — глубокая интеграция с Win32 API (реестр, службы, дескрипторы окон).
- `std.devices`, `std.power` — опрос системных датчиков, уровня заряда батареи и режима энергопотребления.

<a id="1010-мультимедиа-и-графический-интерфейс"></a>
### 10.10 Мультимедиа и графический интерфейс (`gui`, `audio`, `image`)
- `std.gui` — создание нативных окон, меню, элементов управления и WebView-контейнеров.
- `std.audio` — генерация форм волны (синус, пила, треугольник, шум), фильтры, ресемплинг, БПФ-анализ (FFT) и воспроизведение WAV.
- `std.image` — отрисовка изображений, геометрических примитивов, сохранение в PNG/BMP.

<a id="1011-базы-данных-и-логирование"></a>
### 10.11 Базы данных и логирование (`db`, `log`, `metrics`)
- `db.open("sqlite", "file.db")` — работа с локальными реляционными базами данных SQLite.
- `log.info(...)`, `log.warn(...)`, `log.error(...)` — форматированное структурированное логирование.
- `metrics.counter(...)`, `metrics.gauge(...)` — сбор и экспорт телеметрии.
