# Зачем Alca? Сравнение с Python, Go и Deno

[English](why-alca_EN.md) | [Русский](why-alca_RU.md)

Когда разработчик впервые знакомится с новым языком программирования, закономерно возникает вопрос: **«Зачем создавать еще один язык, если уже есть проверенные временем Python, Go и Deno/Node.js?»**

Ответ прост: современный ландшафт разработки вынуждает нас идти на болезненные компромиссы.
- Выбирая **Python**, мы получаем идеальную читаемость и скорость прототипирования, но расплачиваемся медлительностью интерпретатора, проблемами с GIL в многопоточности и кошмаром распространения зависимостей (`virtualenv`, колеса `whl`, несовместимость версий C-библиотек).
- Выбирая **Go**, мы получаем потрясающую скорость компиляции, автономные бинарники и отличную параллельность, но страдаем от шаблонного кода (повторяющийся сотни раз `if err != nil`), отсутствия пайплайнов, срезов списков в стиле functional programming, генераторов и гибкого сопоставления с образцом (pattern matching).
- Выбирая **Deno** или **Node.js**, мы получаем богатство экосистемы JavaScript/TypeScript, но вынуждены тянуть за собой 50-мегабайтный движок V8 Chromium, долгий запуск (до 100 мс) и гигантское потребление памяти даже для элементарных микросервисов и CLI-утилит.

**Alca Lang** спроектирован так, чтобы объединить ключевые достоинства этих инструментов и полностью устранить их слабые места.

## 1. Сводная таблица сравнения

| Критерий | Alca Lang | Python 3.12 | Go 1.26 | Deno / Node.js 20 |
| :--- | :--- | :--- | :--- | :--- |
| **Синтаксис** | Элегантный, чистый (отступы, без лишних скобок) | Элегантный, чистый | Многословный, классический C-like | C-like со скобками и точками с запятой |
| **Система типов** | Строгая статическая + мощный вывод типов | Динамическая (тайп-хинты не проверяются в рантайме) | Строгая статическая | Опциональная (TypeScript требует компиляции) |
| **Параллельность** | Настоящие системные потоки без GIL | GIL (один поток на процесс Python) | Легковесные горутины (CSP) | Однопоточный Event Loop |
| **Холодный старт** | **< 3.5 мс** | ~35–50 мс | < 5 мс | ~60–100 мс |
| **Базовая память (RSS)** | **~2.8 МБ** | ~16–22 МБ | ~4–6 МБ | ~50–70 МБ (V8 Engine) |
| **Развертывание** | 1 автономный бинарник (0 внешних зависимостей) | Требует Python рантайм, venv, зависимости | 1 автономный бинарник | Требует Deno рантайм или node_modules |
| **Пайплайны данных** | Нативный оператор `\|>` | Нет (вложенные вызовы функций) | Нет | Метод-чейнинг (`.map().filter()`) |
| **Pattern Matching** | Да, полноценный `match` с деструктуризацией | Ограниченный `match/case` | Нет (только простой `switch`) | Нет (только `switch`) |
| **Песочница (Sandbox)** | Встроена в ядро VM на уровне опкодов | Нет (полный доступ к хост-системе) | Нет (полный доступ к хост-системе) | Флаги разрешений командной строки |
| **Пакетный менеджер** | Встроенный APM (`alca.lock`, SHA-256) | pip (нет встроенных lockfile без сторонних тулов) | go modules (`go.mod`, `go.sum`) | deno vendor / npm |

## 2. Alca против Python: Скорость и надежность без потери элегантности

Если вы любите Python за чистоту кода, лаконичность и отсутствие визуального мусора в виде бесконечных фигурных скобок, в Alca вы почувствуете себя как дома. Синтаксис Alca интуитивно понятен любому Python-разработчику:

```alca
# Генерация списков, срезы и f-строки
users = ["alice", "bob", "charlie", "david"];
active = [u.upper() for u in users if len(u) > 3];

println(f"Активные пользователи: {active}");
```

### В чем Alca кардинально превосходит Python:
1. **Производительность в 10–35 раз выше**: Alca использует регистровую виртуальную машину и встроенный JIT-компилятор, генерирующий машинные инструкции x86-64 на лету. Тяжелые циклы и математика работают на скорости, близкой к C.
2. **Никакого GIL (Global Interpreter Lock)**: В Python многопоточность ограничена блокировкой интерпретатора. В Alca потоки параллельно используют все доступные ядра процессора без скрытых блокировок.
3. **Безопасность статической типизации**: Ошибки `AttributeError: 'NoneType' object has no attribute 'x'` исключены на этапе компиляции. Alca выводит типы автоматически, поэтому вам не нужно вручную прописывать тип каждой переменной, но компилятор гарантирует типобезопасность.
4. **Компиляция в единый `.exe` или ELF-бинарник**: Больше никаких проблем с тем, что у клиента установлена не та версия Python или не собрались C-зависимости. Команда `alca build app.al -o app.exe` создает полностью независимый файл.

## 3. Alca против Go: Выразительность без рутины и бойлерплейта

Go заслужил признание за надежность и отличную модель развертывания. Alca разделяет философию простоты Go, но избавляет разработчика от монотонного шаблонного кода.

### Пример обработки данных в Go:
```go
// В Go требуется явный цикл и временный срез
var result []string
for _, item := range data {
    if isValid(item) {
        val, err := transform(item)
        if err != nil {
            return nil, err
        }
        result = append(result, val)
    }
}
```

### То же самое в Alca с помощью оператора пайплайна `|>`:
```alca
result := data 
    |> filter(isValid) 
    |> map(transform);
```

### В чем Alca превосходит Go:
1. **Современные функциональные инструменты**: Нативные операторы конвейера `|>`, сопоставление с образцом `match`, генераторы списков и словарей делают код в 2–3 раза короче при сохранении читаемости.
2. **Мягкая и безопасная обработка ошибок**: Вместо постоянного нагромождения `if err != nil` Alca предлагает выразительные потоки ошибок с операторами `try`, `catch`, `or` и защищенным разыменованием `?.`.
3. **Скорость итераций при разработке**: На этапе разработки Alca можно запускать мгновенно как скрипт (`alca run script.al`), не дожидаясь компиляции всего проекта, а перед релизом — собрать в высокооптимизированный статический бинарник.

## 4. Alca против Deno / Node.js: Мощь песочницы без тяжелого движка браузера

Deno доказал важность встроенной безопасности (sandbox) и интегрированных инструментов. Однако использование движка V8 от Google Chrome делает рантайм Deno и Node.js чрезмерно «тяжелым» для системных утилит, микросервисов и встраиваемых решений.

### В чем Alca превосходит Deno/Node:
1. **Мгновенный отклик (<3.5 мс против 80–120 мс)**: Скрипт на Alca успевает выполниться и завершить работу раньше, чем Node.js или Deno закончат инициализацию движка V8. Для CLI-утилит и serverless-функций это критическая разница.
2. **Потребление памяти всего ~2.8 МБ**: Сервис на Alca требует в 20–25 раз меньше оперативной памяти, чем аналогичный микросервис на Node.js (требующий 50–70 МБ). На одном сервере можно запустить сотни микросервисов Alca без риска исчерпания RAM.
3. **Бескомпромиссная песочница в ядре ВМ**: Песочница Alca контролирует доступ к файлам, сети и переменным окружения на уровне байткода виртуальной машины, а не через обертки над JavaScript API.

## 5. Для каких задач Alca подходит идеально?

1. **Высоконагруженные сетевые сервисы и микросервисы**: Минимальное потребление памяти, мгновенный старт, эффективная обработка JSON и HTTP.
2. **Консольные утилиты и DevOps-инструменты**: Быстрый холодный старт, сборка в один переносимый исполняемый файл без внешних зависимостей.
3. **Обработка данных и автоматизация**: Лаконичный синтаксис уровня Python в сочетании со скоростью скомпилированного кода.
4. **Безопасное исполнение стороннего кода**: Встроенная песочница с мандатной моделью разрешений идеальна для плагинов и серверного выполнения пользовательских скриптов.

---

## 6. Резюме

Alca — это не попытка заменить всё сразу. Это прагматичный выбор для тех, кто:
- Устал от медлительности и сложностей развертывания **Python**;
- Устал от шаблонности и жестких синтаксических ограничений **Go**;
- Не хочет мириться с гигантским потреблением памяти и медленным стартом **Node.js/Deno**.

Попробуйте запустить первую программу прямо сейчас:
```bash
alca run examples/hello.al
```
