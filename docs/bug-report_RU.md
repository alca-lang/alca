# Отчет об исправленных дефектах и регрессионном тестировании

[English](bug-report_EN.md) | [Русский](bug-report_RU.md)

В данном отчете перечислены дефекты, выявленные и устраненные в процессе разработки Alca на этапах P0–P6: миграция синтаксиса, инструментарий, паритет движка VM и интерпретатора, строгие сигнатуры типов, кросс-компиляция и безопасность песочницы.

Методология: Alca содержит два основных движка выполнения (Bytecode VM и древовидный интерпретатор), поведение которых обязано побайтово совпадать. Любое расхождение, некорректная компиляция или отсутствие проверки прав песочницы трактуется как критический баг. Исправления всегда вносятся в движок рантайма с фиксацией детерминированным регрессионным тестом.

Текущая статистика:
- Корпус паритета движков: **91 программа**, выполняемая на обоих движках со строгим побайтовым сравнением stdout (`cmd/alca/engine_test.go:TestEnginesAgree`).
- 10 прикладных тестов повседневного использования в каталоге [`tests/`](../tests/).

## P0 — Паритет движков и корректность рантайма (баги #1–#12)

| ID | Симптом | Причина и исправление | Регрессионный тест |
| --- | --- | --- | --- |
| P0-1 | Сравнение `"abc" < "abd"` возвращало неверный результат на VM | Порядок сравнения строк на VM отличался от интерпретатора; логика унифицирована | `engine_test.go` `p26_string_compare` |
| P0-2 | Сложение `a + b` двух списков приводило к ошибке float | В байткод-компиляторе отсутствовала ветка list+list; добавлен вызов конкатенации | `engine_test.go` `p42_list_concat` |
| P0-3 | Ошибки деления на 0 и переполнения сообщали код 500 вместо 400 | VM возвращала общие ошибки 500; коды арифметических ошибок приведены к 400 | `engine_test.go` `p18_div_zero_capture`, `q23_pow_negative_int` |
| P0-4 | Оператор принадлежности `in` проверялся тайпчекером, но не исполнялся | Оба движка переведены на единую реализацию `interpreter.InOp` | `engine_test.go` `p35_membership` |
| P0-5 | `for i in 3` итерировал один элемент на интерпретаторе | Семантика `EvalRange` распространена на одиночные целые числа | `engine_test.go` `q14_range_single_int` |
| P0-6 | `for i in 5..1` выполнял 0 итераций на VM | Нисходящие диапазоны переведены на обработку через `EvalRange` | `engine_test.go` `q12_range_descending`, `q13_range_negative` |
| P0-7 | Индексация на VM игнорировала отрицательные индексы | Добавлена поддержка отрицательных индексов и генерация ошибки 400 при выходе за границы | `engine_test.go` `q01_list_oob`, `q02_list_negative_index` |
| P0-8 | Запись по индексу за границами списка тихо игнорировалась на VM | Добавлена валидация границ с генерацией кода ошибки 400 | `engine_test.go` `q05_set_oob` |
| P0-9 | Имя члена стандартной библиотеки затеняло модуль (например `log`) | Устранено затирание модульного связывания при импорте | `engine_test.go` |
| P0-10 | Корзины гистограммы метрик суммировались дважды | `metrics.histogram` исправлен для единичного учета корзин | `stdlib_test.go:TestMetricsHistogramBucketsAreCumulative` |
| P0-11 | `json_query` возвращал `null` для декодированного map/list | Исправлен проход по декодированным структурам данных | `stdlib_test.go:TestFormatsModule` |
| P0-12 | Ошибки VM теряли код ошибки Alca в CLI | Добавлено сохранение оригинального кода ошибки в формате диагностики | `vm_test.go:TestRaisedErrorReportsItsOwnCodeInDiagnostics` |
