# Интерфейс командной строки (CLI)

[English](cli_EN.md) | [Русский](cli_RU.md)

Сборка исполняемого файла CLI:
```bash
go build -o alca ./cmd/alca
```

## 1. `alca run`

```bash
alca run [--vm|--interp|--jit] [флаги возможностей] <file.al> [аргументы скрипта...]
```

- **Движок по умолчанию**: Bytecode VM. Быстрый стековый виртуальный процессор. Если код использует возможности только для интерпретатора (динамические макросы), он плавно переключается с уведомлением в консоль.
- `--vm`: Требовать строго виртуальную машину. При неподдерживаемых конструкциях возвращает ошибку.
- `--interp`: Принудительно использовать эталонный древовидный интерпретатор.
- `--jit`: Включить многоуровневый JIT-компилятор под AMD64 для горячих функций и циклов.
- Ограничения памяти:
  - `--max-memory=<размер>`: Максимальный объем оперативной памяти (например, `128mb`, `1gb`).
  - `--max-allocation=<размер>`: Максимальный суммарный объем выделений памяти.
- Аргументы после `<file.al>` доступны в скрипте через `cli.args()` из модуля `std.cli`.

---

## 2. `alca check`

```bash
alca check <file.al>
```

Выполняет синтаксический анализ и строгую проверку типов без исполнения кода. При отсутствии ошибок возвращает код `0`; при наличии выводит ошибки компилятора с указанием строк/колонок и завершается с кодом `1`. Идеально подходит для CI/CD и Git pre-commit хуков.

---

## 3. `alca test`

```bash
alca test [флаги возможностей] <file.al>
```

Находит и исполняет код верхнего уровня и все блоки `test "имя" { ... }`. Выводит статистику успешных и упавших тестов. Завершается с ненулевым кодом при провале любого `assert` или тест-блока.

---

## 4. `alca build`

```bash
alca build <file.al> [-o output] [--protect] [--gui] [--target os/arch] [--source] [--embed <path>]
```

Компилирует программу Alca в автономный исполняемый файл без внешних зависимостей:
- **Windows**: Встроенный сборщик нативного формата PE/COFF.
- `--protect`, `-p`: Шифрует полезную нагрузку через AES-256-GCM и обфусцирует имена символов.
- `--noconsole`, `--gui`: Устанавливает подсистему PE в режим GUI (не открывает черное окно консоли при запуске).
- `--source`: Встраивает исходный код и локальные импорты вместо скомпилированного байткода VM.
- `--embed <path>`: Упаковывает ассеты, шаблоны или БД прямо в бинарник (доступны во время выполнения через `use std.embed; embed.read(...)`). Флаг можно указывать многократно для добавления нескольких путей.

---

## 5. `alca dll`

```bash
alca dll <source> [-o output.dll]
```

Компилирует нативный C/C++ код или экспортированные функции Alca (`pub fn`) в нативную динамическую библиотеку (`.dll` на Windows, `.so` на Linux) с нулевыми внешними тулчейнами.

---

## 6. `alca fmt`

```bash
alca fmt [-w|--write] <file.al>
```

Форматирует код Alca по каноническим правилам (отступы в 4 пробела, форматирование выражений, сохранение комментариев). С флагом `-w` перезаписывает файл на месте с проверкой AST-цикла для безопасности.

---

## 7. `alca repl`

```bash
alca repl [флаги возможностей]
```

Интерактивная консоль с пошаговой статической типизацией, поддержкой многострочных блоков и мгновенным вычислением выражений. Для выхода введите `exit` или `quit`.

---

## 8. `alca lsp`

```bash
alca lsp
```

Запускает сервер Language Server Protocol через стандартные потоки ввода-вывода. Поддерживается в VS Code, Neovim, Helix, Sublime Text. Предоставляет автодополнение, подсветку ошибок и информацию при наведении (hover).

---

## 9. Флаги песочницы (Capabilities)

По умолчанию программы запускаются в строгой песочнице с запретом любых системных ресурсов. Права выдаются явно:

| Флаг | Назначение |
| --- | --- |
| `--allow-read` | Чтение любых файлов на диске. |
| `--allow-read=<путь>` | Чтение только указанного файла или подпапки. |
| `--allow-write` | Запись, создание и удаление любых файлов. |
| `--allow-write=<путь>` | Запись только в границах указанного пути. |
| `--allow-net` | Любые сетевые соединения (клиент и сервер). |
| `--allow-net=<хост[:порт]>` | Сеть только к конкретному хосту, порту или маске домена (`*.example.com`). |
| `--allow-run` | Разрешение запуска внешних подпроцессов через `exec.Command` / `std.process`. |
| `--allow-run=<команда>` | Разрешение запуска только конкретного бинарника. |
| `--allow-env` | Чтение и запись переменных окружения. |
| `--allow-env=<имя>` | Доступ только к конкретной переменной окружения. |
| `--allow-ffi` | Загрузка внешних нативных динамических библиотек (.dll, .so). |
| `--allow-ffi=<путь>` | Загрузка только конкретной библиотеки. |
| `--allow-all` | Безусловно предоставить все права (read, write, net, run, env, ffi). |
| `--` | Завершает обработку флагов CLI; последующие токены передаются как аргументы скрипта. |

Попытка доступа без флага вызывает ошибку рантайма (`code 403`) и фиксируется в журнале аудита безопасности.
